# PPT Department 2 Page Patterns

## Cover

Use for first slide.

Layout:

- Light off-white background.
- Center-right or centered title group.
- Chinese title in red/dark navy; English title below in smaller text.
- Bottom center slogan `Make a Well Change.` if suitable.
- Thin horizontal red/dark line near bottom.
- Minimal decoration.

## Sparse Divider / Thesis Page

Use to mark a major idea or transition.

Layout:

- Mostly empty light background.
- One centered sentence.
- Highlight 1-3 keywords in red and/or blue.
- Optional small English subtitle below.

Good for:

- Pain-point conclusion.
- Chapter transition.
- Final statement.

## Why Now / Problem Framing

Use to explain urgency.

Layout options:

- Two opposing cards with a central circle or product name.
- Left side: internal efficiency or operational pressure.
- Right side: customer demand or external requirement.
- Use red for pressure/risk, navy/blue for system response.

Title pattern:

- `Why Now`
- `Internal efficiency release × Customer demand fulfillment`

## Evolution Timeline

Use for product evolution or phased history.

Layout:

- Horizontal three-phase flow.
- Phase labels spaced as `P H A S E  0 1`, `P H A S E  0 2`, `P H A S E  0 3`.
- Use large `01`, `02`, `03` number blocks.
- Include 2-3 bullets for limitation or improvement under each phase.

Style:

- Century Gothic for phase and numbers.
- Muted gray/blue blocks for early stages, strong navy/red for final stage.

## Construction Goal / Capability Pillars

Use to state product goals or solution targets.

Layout:

- Four pillar cards across the page.
- Each card includes a compact icon or small diagram, a bold heading, and 1-2 lines of explanation.
- Use thin vertical separators or subtle card outlines.

Examples:

- 指标底座 / 统一口径
- 异常洞察 / 根因诊断
- 经验沉淀 / 方案复用
- 敏捷定制 / 低成本响应

## Architecture Diagram

Use for product architecture, system framework, or BGMH collaboration framework.

Layout:

- Layered blocks or hub-and-spoke system diagram.
- Keep the top row as application or service layer.
- Middle row as AI/system capability layer.
- Bottom row as data/infrastructure layer.
- Use arrows to show flow only where the flow matters.

Style:

- Navy blocks for system modules.
- Green blocks for AI or intelligence layer.
- Gray blocks for data or support layer.
- Red label for the core platform or key node.

## Dual-Mode Analysis Page

Use for data platform capability pages.

Layout:

- Title: Chinese capability statement plus English subtitle.
- Two large panels: macro/topic analysis and time-series/deep dive.
- Use a narrow vertical switch or divider between panels.
- Include screenshots or sample UI panels inside each side.

Style:

- Light background with dark framed content, or dark panels on light background.
- Red title rule.

## Diagnostic Loop Page

Use to explain "from sensing to action" capabilities.

Layout:

- 3-4 stage flow: anomaly sensing -> root cause analysis -> strategy recommendation -> execution feedback.
- Each stage has a screenshot/card and short explanation.
- Use arrows or sequential numbers.

Style:

- Use red for abnormal nodes and blue/green for solution or normal operation.
- Keep explanatory text short.

## Scenario Card Assembly Page

Use for modular products, metric components, scene building, or solution libraries.

Layout:

- Left: atomic metric pool or input library.
- Middle: assembled cards or scenario modules.
- Right: themed dashboard or personalized output.
- Use grouped small cards with consistent dimensions.

Style:

- Category colors can be richer here, but keep every category aligned and labeled.
- Use thin outlines and small text.

## Value Summary

Use to summarize product value.

Layout:

- Large red keywords on the left: `降成本`, `提效率`, or similar.
- Right side: 2x2 or 2x3 grid explaining value dimensions.
- Use a red line or red side bar to connect headline to evidence.

Rules:

- Keep each value card to one heading and one short supporting line.
- Tie value to measurable business or delivery outcomes where possible.

## Roadmap

Use for implementation plan or construction route.

Layout:

- Table or swimlane grid.
- Columns: time periods or phases.
- Rows: phase goal, key direction, key capability, deliverables.
- Use small colored phase tags or letters.

Style:

- Light table on white or dark table on `202631`.
- Use blue phase accents for planned work.
- Use red only for milestones, gates, or critical risks.

## Closing

Use for final slide.

Layout:

- Light background.
- One sentence centered.
- Emphasize the most important phrase in red.
- Optional slogan below.

Examples:

- `让港口的每一份数据，都算得出价值。`
- `空天突破，陆海联动`
