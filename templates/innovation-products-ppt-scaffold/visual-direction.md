# 项目视觉导向说明

> 用途：这份文件是单个 PPT 项目的视觉 brief，不是新 agent，也不是通用 skill 规则。它回答“最终页面应该看起来像什么”，用于指导蓝图、样页、组件选择、渲染复核，并交给现有视觉设计师 agent 参考。

> 写法要求：这里可以写本项目的受众、故事线、页码、截图槽位和视觉偏好；如果某条经验具有通用价值，必须先脱敏抽象，再提升到 skill 的 reference 或 LESSONS 中。

## 1. 视觉目标

根据本次项目受众、主题和品牌风格，定义最终 PPT 的视觉目标：

- 第一眼应该给人的感觉。
- 整套 PPT 应该如何体现故事节奏。
- 页面细节应该如何体现可信度和设计感。

## 2. 设计气质

- 是否克制、专业、工程化。
- 是否需要强视觉张力、证据感、场景感或产品感。
- 哪些内容应该留白，哪些内容可以高密度表达。
- 图形与线条各自承担什么关系，不能只写“图形为主”。
- 哪些主 surface 使用阴影，哪些 support/inset/control 必须平面。
- 状态 rail 是否启用；启用时只对应哪些真实状态。
- 结论放在副标题、正文闭环还是确有语义的 decision band。

### 本项目留白与密度策略

- 哪些页面需要低密度焦点、停顿、张力、图片强调或章节换气。
- 哪些页面需要高密度机制、证据或比较。
- 低密度页的 `whitespaceIntent` 和视觉焦点是什么。
- 本项目不应沿用上一套 PPT 的哪些布局、视觉签名或组件组合。

## 3. 页面表达模式组合

整套 PPT 不应反复使用同一种版式。按页面任务规划表达模式：

| 表达模式 | 适合页面 | 使用原则 |
|---|---|---|
| 大字张力 | 问题、收益、转场、结论 | 少字、高对比、强焦点 |
| 概念图 | 定义、边界、框架 | 用空间关系表达逻辑 |
| 流程图 | 执行流、协作流、状态流 | 人、AI、文件、工具分层清楚 |
| 截图证据 | 文件、系统、QA、agent、产物 | 有来源、裁剪规则和解释锚点 |
| 工具树 / 决策流 | 工具系统、组件选择 | 先表达判断逻辑，再落组件 |
| 生命周期环 | 反馈、自进化、治理 | 闭环步骤必须具体可操作 |
| 图片 / image2 | 场景、隐喻、氛围 | 简单、无小字、不承担精确逻辑 |

## 4. 图片、截图和 image2 使用原则

- 真实文件、目录、markdown、QA、agent、artifact manifest：优先真实截图。
- 概念隐喻、场景氛围、单一示意：可以使用 image2，但必须简单、无小字、无复杂流程。
- 复杂流程、架构、状态机：优先 PPT 可编辑图形。
- 截图槽位必须在蓝图阶段预留。

## 5. 禁止出现的 AI 味设计

- 每页底部默认总结框。
- 大量白色卡片均匀铺满页面，但没有视觉主次。
- 红色到处描边，却说不清每个红色代表什么。
- 字号为了塞内容越缩越小。
- 图形和文字贴边、压框、溢出。
- 线条歪斜、连接误导。
- 修改页退化成同尺寸卡片墙，或与已批准锚点失去同一套视觉语言。
- Base2 只有图形没有关系线，或所有矩形统一加阴影。
- 所有机制页都长成同一种“框 + 箭头 + 小字”。
- image2 图过复杂、背景过花、带小字或看不懂。

## 6. 渲染后看图标准

最终 PPT 必须用渲染图说话。每次输出预览图或成品页后，按下面顺序看：

1. 远看：contact sheet 缩略图里，是否能看出每页不同的视觉任务？
2. 中看：单页 50% 缩放时，主体是否居中、焦点是否明确、红色是否有意义？
3. 近看：文字是否可读，是否有重叠、溢出、压框、歪线？
4. 连看：相邻页面是否有故事节奏，而不是重复同一个版式？
5. 讲看：假设现场汇报，图形是否能帮助听众理解？
6. 改看：如果是 delta revision，修改页是否仍与本轮批准锚点共享同一套构图、阴影和状态语言？

## 7. 视觉设计师 agent 的重点

- 哪些页应该从卡片页改成机制图、截图证据、大字页或图像页。
- 哪些页红色没有语义，需要降级为结构色或中性色。
- 哪些页主体偏上、偏散、偏空，需要重新组织视觉重心。
- 哪些页适合用真实截图或简单 image2。
- 哪些重复版式应该打散。
