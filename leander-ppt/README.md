# Leander PPT Skill 说明

## 一、概述：定位与设计动机

Leander PPT 用于将源材料（项目文档、产品资料、会议纪要等）转化为一份正式、可编辑的 PPTX。

单纯依赖一段"把这份材料做成好看的 PPT"式的提示词生成幻灯片，通常会出现三类问题。其一，页面结构和视觉风格在生成过程中逐渐偏离预期，往往要等到看到成品才发现方向有误，只能整体重做。其二，一处改动（例如统一调整字号）会波及全篇，却难以逐页核实影响范围，导致局部质量下降。其三，成品在视觉上呈现出典型的生成式痕迹，例如颜色使用没有含义、留白比例失衡、多页版式雷同——这类问题单靠提示词难以约束。

Leander PPT 将 PPT 生产拆解为若干个具有明确产出物与检查节点的阶段，以流程约束质量，而非依赖单次生成的效果。

## 二、设计原则

以下三条原则构成了整套流程的设计依据。

**1. 结构先于视觉**

内容逻辑与页面结构须先于视觉设计确认。在配色、组件、版式确定之前，先完成大纲——即每一页讲什么、以什么形式呈现、依据什么素材，并与需求方核对一致。这一步成本很低，但省略它是全篇返工最常见的原因：结构问题一旦拖到样稿甚至全篇制作完成后才发现，修改代价会成倍增加。

**2. 页面为最小生产单元**

每一页在物理上是独立的构建单元，拥有各自的构建代码、验收记录与渲染结果。这带来两点好处：其一，定位问题时可精确到具体页面，无需在整份文件中排查；其二，修复问题时只需重新生产受影响的页面，其余页面不受牵连。仅当问题源于多页共享的主题或组件时，才需要扩大修复范围并重新核查全篇。

**3. 完成以可验证产物为标准**

一次生成不等于一次合格的产出。每次生产都须经过渲染（转化为可视化图片）与检查，确认内容、版式、配色符合既定标准后，才视为完成。判断依据是渲染图与检查记录这类可验证的产物，而非"看起来生成完了"这一主观印象。

## 三、工作流程概览

从源材料到成品，生产过程经过以下几个阶段：

1. **确定内容与结构**：理解材料，梳理受众、目标与要点，产出一份逐页大纲。
2. **确定视觉风格**：根据用途（内部汇报或对外展示）选定主题，明确色彩、字体、版式规范。
3. **制作代表性样稿**：选取最具代表性、最容易暴露问题的若干页面先行制作并核对，验证结构与风格是否符合预期。
4. **批量生产**：样稿确认后，按大纲完成全部页面。
5. **反馈与修复**：根据意见定位问题所在的页面或组件，修复后重新核验。

流程中设有两个必须停下确认的节点：

- **结构确认**（第一阶段之后）：逐页核对大纲，确保页面数量、顺序、内容形式与预期一致。这一节点以很低的成本排除方向性错误，避免在大量页面制作完成后才发现结构问题。
- **样稿确认**（第三阶段之后）：核对代表性样稿的视觉风格，确认色彩、字号、版式密度等是否符合预期。这一节点排除的是风格性错误，即结构正确但视觉呈现不满意的情况。

两个节点分别对应两类最容易导致整体返工的错误，因此均不可省略。

## 四、Skill 组成

Skill 由三个功能层次构成：

**规则与流程层**：定义生产流程各阶段的顺序、每个阶段的产出要求，以及各类页面的设计规范，包括配色使用原则、字号层级、版式选择依据等。这一层是经验的载体，随实践积累持续补充与修订。

**生产工具层**：包含可直接复用的主题（预设的配色、字体、版式规范）与组件库（预先实现的常见图表、流程图、架构图等页面形式），以及将构建代码转化为可视化预览图的渲染工具。实际制作环节直接调用这一层完成生产。

**质量校验层**：由独立于制作过程的校验环节构成，依据既定标准对渲染结果逐项核查，输出通过与否的结论及具体问题清单。"独立"意味着校验不预设制作过程中的判断，仅依据最终呈现结果评估。

三层分工明确：规则层回答"应该怎么做"，工具层负责"如何做出来"，校验层确认"是否做对了"。

## 五、图形生成机制

页面的视觉呈现遵循统一的判断逻辑：制作某一页面之前，先明确该页需要向观众传达的关系类型——是流程先后、层级归属、数据对比，还是某种结构关系。明确关系类型之后，再选择表现形式，通常有三种路径：

- 内容适合以图形结构表达（如流程、矩阵、时间线、架构图）时，从组件库中选取合适的现成组件；
- 内容是复杂或写实的场景（如实景画面、点云可视化）时，预留图片区域并生成对应的图片描述，交由图像生成工具或实拍素材填充；
- 内容是真实数据图表，或需要专门渲染引擎处理的图形（如三维场景、地图）时，交由外部渲染工具生成后以图片形式插入。

三种路径服务于同一原则：图形用于表达内容中的具体关系，而非作为装饰；采用哪种表现形式取决于内容本身适合怎么表达。

## 六、迭代与积累机制

每一次根据反馈完成的修复，都会被记录为一条经验：问题的类型、成因，以及具有普遍性的解决方式。当同一类问题反复出现，这条经验会被提炼为一条通用规则，纳入后续生产主动核查的检查清单。

这一机制使 Skill 在持续使用中积累起一份不断增长、来自实际反馈的检查依据，而不长期停留在最初设定的规则上。使用次数越多，可依据的经验越完整，同类问题重复出现的概率随之降低。

## 七、总结

Leander PPT 要解决的核心问题是：如何让 AI 生成的 PPT 达到可直接使用的正式水准，而非需要大幅返工的草稿。其方法是将生产过程拆解为具有明确产出物与检查节点的若干阶段，以页面级别的独立构建保证问题可定位、可修复，以渲染后核查而非主观判断作为完成的标准。

这套方法适用于对结构准确性与视觉规范性有较高要求的正式 PPT 制作场景，包括内部汇报、产品介绍、项目复盘、对外演示等。它不适合追求极致速度、可接受草稿质量的场合——在那类场合，流程本身的确认节点会构成不必要的开销。
