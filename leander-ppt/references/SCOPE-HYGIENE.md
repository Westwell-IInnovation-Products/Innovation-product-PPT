# 作用域边界与样例卫生

本文件用于编辑 Leander-PPT skill 本体、通用 reference、框架模板、组件库和示例时，区分“通用规范”和“项目事实”。

## 核心原则

通用规范可以描述方法、约束、检查项和抽象模式；不能携带某一次 PPT 的具体内容。

项目事实包括：

- 当前 PPT 标题、页码、章节名和故事线。
- 当前工作流状态，例如某项目正在重做大纲或蓝图。
- 用户对某几页的具体反馈。
- 客户、部门、项目、产品、截图、文件夹路径和敏感素材。
- 某一次交付的具体数据、案例、收益数字和结论。

这些内容应进入项目目录，而不是进入通用 reference 或模板规则。

## 文件分层

| 层级 | 可以放什么 | 不应该放什么 |
|---|---|---|
| `SKILL.md` | 路由、阶段、硬关卡、必须读取的 reference | 当前项目页码、当前 PPT 标题、某次反馈的具体修复方案 |
| `references/*.md` | 通用方法、检查规则、流程设计、抽象后的经验 | 某一页的专属内容，除非明确标注为“示例” |
| `templates/leander-ppt-scaffold/` | 可复用框架、占位数据、主题默认值、示例页面 | 当前项目的故事线、截图、客户数据、阶段状态 |
| `agents/*.md` | 角色职责、输入输出、失败规则 | 某个项目的任务结论或页级修改意见 |
| 项目 `state/feedback-log.md` | 当前项目原始反馈和具体修复证据 | 复制到共享 Skill；提升前必须脱敏、抽象和回归 |
| `LESSONS.md` | 已抽象、仍然有效的活跃规则 | 未归因的零散反馈或项目偏好 |
| 项目目录 | 当前 PPT 的 `outline.md`、`visual-direction.md`、`layout-blueprint.*`、`pages/*`、`state/*` | 可复用 skill 规则，除非准备提升并脱敏 |

## 视觉导向文件的边界

`visual-direction.md` 是项目级视觉 brief，不是新 agent。

- 它回答“这套 PPT 应该看起来像什么”。
- 它可以包含当前 PPT 的页码、截图槽位、章节节奏和用户偏好。
- 它由主流程、策划师（含布局蓝图）、视觉设计师和 reviewer 读取。
- 它不新增角色，不替代 `visual-designer-zh`。
- 当其中的规则具有通用价值时，需要先脱敏、抽象，再提升到 `VISUAL-COMPOSITION.md`、`SLIDE-CRAFT.md`、`PAGE-DESIGN-METHOD.md` 或 `LESSONS.md`。

## 样例写法

可以写：

```text
示例：某机制页可以使用“中心能力层 + 外圈机制节点”的表达方式。
```

不要写：

```text
P9 使用 Harness 架构中心发散图，标题为某某内部分享。
```

除非这段内容位于项目目录，或者明确处在“示例/历史案例/反馈归档”小节中。

## 提升规则

从项目反馈提升为通用规则时，必须通过三步：

1. **脱敏**：去掉项目名、页码、客户名、截图路径、当前阶段。
2. **抽象**：把“这一页怎么改”改成“这类页面应该如何判断和处理”。
3. **落位**：根据性质放入合适位置。

落位建议：

- 视觉质量规则：`VISUAL-COMPOSITION.md`
- 页面表达方法：`PAGE-DESIGN-METHOD.md`
- 蓝图与故事节奏：`LAYOUT-BLUEPRINT.md`
- 组件选择和组件抽象：`COMPONENT-LIBRARY-DESIGN.md`
- QA 检查逻辑：`DYNAMIC-QA.md` 或 `QA.md`
- 仍需观察的经验：`LESSONS.md`

## 编辑前自检

- [ ] 这段内容是通用规则，还是当前项目事实？
- [ ] 如果是样例，是否明确写了“示例”？
- [ ] 是否出现了当前 PPT 标题、页码、客户名、具体截图或项目路径？
- [ ] 是否把历史反馈日志当成默认生产规则？
- [ ] 是否把项目级 `visual-direction.md` 误当成一个新 agent？

## 可执行关卡

编辑 Skill 本体、通用 reference、agent 规格或框架后，运行：

```bash
node templates/leander-ppt-scaffold/tools/lint-scope-hygiene.js --skill-root .
```

关卡至少阻断：

- 通用脚本中的绝对本地路径；运行时路径必须通过项目根目录、环境变量或工具发现获得。
- 通用关卡依赖某次历史版本的固定产物名；文件名保持稳定，版本写入 JSON 内容。
- 未标注为示例的页码专属修复指令；先抽象为页面关系、表达模式、风险类型或组件缺陷。

这个关卡只负责发现高置信度泄漏，不代替人工判断。项目可以包含自身事实；需要检查的是准备分享的 Skill 层。
