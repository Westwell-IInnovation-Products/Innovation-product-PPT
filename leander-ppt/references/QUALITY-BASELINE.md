# Leander PPT 质量基线

本基线定义正式多页 PPT 的最低完成度。目标不是复制某一套 PPT 的内容或风格，而是确保后续项目至少具备完整叙事、充分内容、可解释视觉、真实证据和可演讲性。

## 一、整套内容基线

长 PPT 在大纲阶段必须建立 `source-evidence-index.json`。页数超过素材可支撑能力时，选择补充研究、补充截图/图片、合并页面，或记录用户明确接受的低证据边界；不得靠改写和拆句制造页数。

正式 PPT 必须同时回答：

1. 听众为什么要关心。
2. 当前环境或事实为什么让问题值得讨论。
3. 真正要解决的问题和边界是什么。
4. 提供的方案是什么。
5. 方案如何运行、如何验证、有什么限制。
6. 如何落地，预期产生什么变化。

不同类型 PPT 可以调整顺序，但不能只有背景、只有方案或只有结论。长 PPT 应有明确章节承接、节奏变化和最终收束。

## 二、单页内容基线

每个内容页至少包含以下四层：

- **核心主张**：一句可以被讲出来的 takeaway，不是栏目名。
- **支撑内容**：事实、案例、步骤、模块、关系、数据或产物，足以支撑主张。
- **边界证据**：来源、实现状态、估算边界、截图、文件、公开材料或待确认项。
- **听众价值**：这一页帮助听众理解、判断或行动什么，并能自然承接下一页。

内容丰富度不等于文字多，也不等于每页都高密度。普通内容页通常应能支持约 30-90 秒有效讲述；大字页、转折页、图像页或刻意停顿页可以更短、更克制。最低解释结构可以分布在页面、口播备注和来源材料中，不要为了“完整”把所有内容都塞到画面上。

低密度页面必须有明确的 `whitespaceIntent` 和 `densityRationale`，例如建立焦点、制造停顿、形成张力、突出图片或给复杂章节换气。没有设计理由的空白才是缺陷。

## 三、不同页面的最低解释结构

| 页面类型 | 至少讲清楚 |
|---|---|
| 问题/痛点 | 现象、原因或失败模式、影响、为什么现有办法不够 |
| 定义/概念 | 定义、边界、与相邻概念的关系、为什么有用 |
| 趋势/案例 | 主体、做了什么、得到什么结果或进展、与本页主题的关系、来源边界 |
| 框架/架构 | 核心对象、组成层、层间关系、每层职责、后续如何展开 |
| 流程/编排 | 输入、步骤、人工/系统责任、阶段产物、确认或异常路径 |
| 状态/记忆 | 原始问题、保存对象、状态如何恢复、证据位置、限制 |
| 工具/组件 | 工具分类、适用条件、选择逻辑、输出形式、失败或降级路线 |
| QA/评估 | 固定底线、页面动态检查、证据、责任角色、失败后的动作 |
| 自进化/治理 | 记录、归因、抽象、提升、验证、衰减或退出条件 |
| 收益/效果 | 原始基线、发生的变化、可验证结果、不能量化的边界 |
| 迁移/扩展 | 可迁移能力、目标场景、具体用法、解决的问题、适用边界 |
| 资料/参考 | 材料名称、链接或来源、为什么值得看、适合学习什么 |

## 四、视觉完成度基线

- 页面视觉形式必须服务内容关系，不能只把文字装进方框。
- 每个项目必须根据自己的主题、受众、故事和素材重新规划页面布局；本 Skill 提供关系模式和组件候选，不提供固定页序或固定版式答案。
- 长 PPT 应混合机制图、证据页、截图、流程、对比、大字页、图片或其他适配形式。
- 每页必须声明颜色意图；强调色只承担一个清楚的逻辑角色。
- 主体围绕正文视觉中心组织，文字不溢出，同级元素统一，连线不误导。
- 真实文件、目录、系统、Agent、QA 和产物优先使用真实截图。
- image2 只承担简单场景或隐喻，不承担精确流程和密集文字。

## 五、内容真实性基线

- 外部案例、公司动作、最新研究、数字和日期必须核实来源。
- 已实现、部分实现、提议、估算和公开参考必须明确区分。
- 不把思考过程、制作备注、设计解释或“这一页要讲……”直接放进对外 PPT。
- 不编造效率倍数、客户结果、产品能力或实施状态。

## 六、可演讲性基线

最终阶段由汇报人检查：

- 每页能否用一句话讲清主旨。
- 前后页转场是否自然。
- 图形是否降低解释成本。
- 关键概念是否有必要的口播补充。
- 哪些事实需要会前更新或核实。

## 七、机器门禁

每个项目必须保留 `quality-target.json`。正式流程默认整体质量目标不低于 8/10，并分别覆盖内容、故事、视觉、可读性、证据和可讲述性。项目可以提高目标，不得为了节省 Token 下调最低质量线。

锚点样页必须覆盖主题/封面、全套最常见的普通内容表达、复杂结构和证据/图片四类代表性风险；同一页面可以同时覆盖多个类别。只验证封面、最复杂页和截图页而漏掉占比最高的普通页，不能锁定全套质量。

页面生产前后运行：

```bash
node tools/verify-quality-baseline.js
```

它检查页面合同、内容边界、截图证据、视觉与 QA 合同，以及长 PPT 的表达模式多样性。低密度页可以减少内容槽位，但必须说明留白意图。机器通过只是质量下限；渲染图仍必须经过视觉设计师、审阅员和汇报人判断。
